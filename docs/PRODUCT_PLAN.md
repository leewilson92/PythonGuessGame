# 极简个人财务 App — 设计方案（MVP）

## Context（为什么做、给谁做）

用户想给自己做一个**极简的个人记账/财务 App**。痛点：市面记账软件功能臃肿、开屏广告、强制注册。
用户不是简单要"流水账"，经过讨论确认他真正想要的是一个**能看财务全貌的个人面板**（净身价 = 资产 − 负债的思路），只是第一版先聚焦"花销 + 房贷"。

两个普通记账 App 做不好、而用户特别在意的点：
1. **房贷/负债**：用户是**混合贷（公积金贷 + 商业贷，利率不同）**，要按月记还款、看负债下降。
2. **银行卡优惠**：刷卡常有优惠（原价 10 / 优惠 2 / 实付 8），要逐笔记录、看累计省了多少，并且**多卡对比"哪张卡更省"**。

> 本窗口只做**方案设计与产品打磨**，已与用户做了多轮深入讨论。具体编码由后续单独的开发 agent 完成。
> 当前 git 仓库原本是个无关的 Python 猜谜小游戏，本项目从零开始。分支：`claude/expense-tracker-design-h2c1wi`。

## 已与用户逐条确认的决策

| 项目 | 决定 |
|---|---|
| 平台 | iPhone（iOS），目标上架 App Store |
| 技术栈 | 原生 **Swift + SwiftUI + SwiftData**，iOS 17+ |
| 存储 | **本地优先**。iCloud（CloudKit）同步留到第二阶段，用 Apple ID，免注册 |
| 注册/广告 | **无注册、无广告、无网络请求**，打开即用 |
| App 定位 | 个人**财务面板**（净身价思路）。**第一版范围 = 花销 + 房贷负债**，资产端（存款等）留到下一版 |
| 房贷 | **告诉条件、自动算**；支持**混合贷（两部分各自利率/期数）** |
| 优惠 | 逐笔记原价/优惠/实付；**做多卡对比，但只放在报表里、不拖慢日常记账** |
| 自动记账 | 第一版不做（iOS 限制，详见约束） |
| 记账习惯 | 用户以**扫码/刷卡为主**，现金少 → 日常记账要快、要有支付方式字段 |
| 构建 | 用户有 Mac，可用 Xcode 构建/上架 |

## ⚠️ 重要约束（开发 agent 与用户都要清楚）

1. **本开发环境是 Linux 容器，无法编译/运行/真机调试/上架 iOS app。** 开发 agent 在这里只能产出 Swift 源码 + 工程文件；真正构建、运行、上架必须在用户的 **Mac + Xcode** 上完成。
2. 上架 App Store 需要 **Apple 开发者账号（99 美元/年）**。
3. **iOS 不允许 app 读取微信/支付宝支付通知**（无 Android 那种通知监听）。未来"自动记账"在 iOS 上的天花板 = Siri 快捷指令 / 系统分享 / 导入支付宝·微信账单 CSV，永远做不到后台全自动。第一版不涉及。

## 核心产品决策（讨论中打磨出来的关键点）

- **两种财务视角并存**（用户明确要的）：
  - **本月支出（消耗口径）** = 日常消费实付 + 房贷**利息**。
  - **本月现金流出（现金口径）** = 日常消费实付 + 房贷**全额还款**。
  - 同一批数据两个数字并列，互不矛盾。
- **房贷本金 vs 利息**：本金部分只减少负债、不计入"支出"；利息才是真支出。这保证"本月花了多少"不被房贷虚高。
- **"简单"的正确定义**：守住"日常记一笔要快（3 秒）"；功能多但不挡日常流程，就不算复杂。多卡对比因此可做——记账时最多多一个"选卡"动作（有默认值、可不选），对比是后台自动算的报表。
- **延迟返现**（过几天才到账的优惠）：第一版先不做，列入路线图。
- **信用卡不能重复计**（用户明确指出）：信用卡消费在**刷的当时**就记为支出；之后"还信用卡"那一步**不另记为支出**，它只是现金真正离开（现金流事件）。否则会把同一笔钱算两遍。

## 现实场景与边界（多轮讨论后确认）

- **数据备份（v1 必做的安全网）**：v1 全本地、无 iCloud，手机丢/坏/换机会丢全部数据。因此第一版就提供**导出/导入备份文件**（一键导出，自己存到 iCloud 文件/微信/邮箱；换机导入恢复）。v2 上 iCloud 同步后此事自动化。
- **房贷"自动算"留两个手动口子**（用户会碰到提前还款 + 利率变动）：
  - **提前还款**：可录入一笔提前还款，App 据此更新剩余本金、重算后续月供/期数。
  - **改利率**：商贷 LPR 浮动，可手动改年利率并重算（公积金一般固定）。
  - 自动算管 90% 日常，这两个口子兜住真实差异。"按银行实扣微调"用户没选，暂不做。
- **退款 / 转账·AA / 借还钱**：用户说都不常碰到，v1 **不专门建模**，按普通一笔记即可（退款可记成一笔收入或负支出）。列入路线图细化。
- **隐私锁 / 收入端**：用户当前只自己用，**v1 不做** Face ID 锁，也暂不记收入。Face ID 留到"上架时"再加；收入端随资产模块（v2）一起做。因此 v1 的"现金流"口径只显示**现金流出**，不算净现金流。

## MVP 功能范围（第一版只做这些）

- **记一笔**：金额（实付）、可选原价（自动算优惠）、分类、**支付方式/卡**（可选、默认上次）、日期（默认今天）、备注。键盘优先、默认值齐全，主打快。
- **优惠**：逐笔 `优惠 = 原价 − 实付`；列表与概览显示累计省了多少。
- **多卡对比**：支付方式内置微信/支付宝/银行卡（用户自定义增删）；概览里被动展示"本月哪张卡省最多"。
- **房贷（混合贷）**：拆成「公积金贷 + 商贷」两部分，各填一次（剩余本金 / 年利率 / 剩余期数 / 还款方式）；每月"确认本月还款"→ 自动按等额本息拆本金利息、自动减负债。**支持提前还款（重算）和改利率（重算）两个手动口子。**
- **数据备份**：一键导出/导入备份文件（安全网）。
- **概览**：本月支出（消费+利息）、本月现金流出（含房贷全额）、本月优惠合计 + 最省的卡、房贷剩余总额 + 已还本金。
- 全本地存储，无登录、无广告、无网络。

**第一版明确不做**：资产/账户余额与净身价、收入端记录、iCloud 同步、Face ID 锁、图表、预算、延迟返现、等额本金（默认只等额本息）、退款/转账/借还专门建模、自动记账、CSV 导入、多币种（默认人民币）。

## 数据模型（SwiftData @Model）

```
Transaction
  id, date
  actualAmount: Decimal       // 实付
  originalAmount: Decimal?     // 原价，可空；省下 = originalAmount - actualAmount
  kind: .expense / .income
  category: Category
  paymentMethod: PaymentMethod?   // 可空，用于多卡对比
  note: String

Category
  id, name, icon(SF Symbol), kind
  // 首启种子：餐饮/交通/购物/日用/居住/通讯/娱乐/医疗/人情；收入：工资/其他

PaymentMethod                  // 支付方式/账户，用于多卡对比
  id, name, type(.wechat/.alipay/.bankCard/.creditCard), icon
  // 信用卡消费照常记为支出；"还信用卡"不另记支出，避免重复计

Loan                           // 一套房贷（可含多部分）
  id, name                     // "房贷"

LoanTranche                    // 房贷的一部分（公积金贷 / 商贷）
  id, name
  openingPrincipal: Decimal    // 期初剩余本金
  annualRate: Decimal          // 年利率
  remainingTerms: Int          // 剩余期数（月）
  repaymentMethod: .equalInstallment   // 等额本息（MVP 默认）
  loan: Loan
  // 当前剩余 = openingPrincipal − Σ payment.principal（计算属性）

LoanPayment                    // 每月还款记录（确认时按公式算好存下）
  id, date
  totalAmount, principal, interest: Decimal
  tranche: LoanTranche

LoanEvent                      // 影响计算的手动事件
  id, date, tranche
  type: .prepayment / .rateChange   // 提前还款 / 改利率
  amount: Decimal?               // 提前还款金额（type=.prepayment）
  newAnnualRate: Decimal?        // 新利率（type=.rateChange）
  // 重算从该事件之后生效：剩余本金、后续月供/期数据此更新
```

设计要点：
- 金额一律 `Decimal`，不用 `Double`，避免浮点误差。
- 优惠、负债剩余均为**计算得出**，不冗余存储，避免不一致。
- 等额本息月供公式：`M = P·r·(1+r)^n / ((1+r)^n − 1)`，其中 `r = 年利率/12`、`n = 剩余期数`；当月利息 `= 当前剩余本金 · r`，当月本金 `= M − 利息`。两部分各自计算后相加得整套房贷的月供/负债。

## 界面结构（SwiftUI TabView，3 个 Tab）

1. **记账**：列表按日期分组（每笔显示实付 + 省下多少）；右上「+」弹出"记一笔"表单（金额键盘优先、支付/收入分段、分类、可选原价、可选支付方式默认上次、日期默认今天、备注）。
2. **房贷**：顶部负债总剩余卡片；下面公积金贷 / 商贷两张分卡（各自剩余、利率、剩余期数）；「确认本月还款」按钮自动拆分并入账；二级入口「提前还款」「改利率」触发重算；还款历史列表。
3. **概览**：四块小卡——本月支出（消费+利息）、本月现金流出（含房贷全额）、本月优惠合计 +"最省的卡"、房贷剩余 + 已还本金。资产端下一版接入后，此页进化为"净身价"。页内/设置入口提供**导出·导入备份**。

风格：系统原生组件、深浅色自适应、无引导页、打开即用。

## 验证方式（在用户 Mac 上）

本环境无法验证 iOS 构建，需在 Mac 上完成：
1. `xcodegen generate` → Xcode 打开 → 选模拟器 Run。
2. 记一笔含原价/优惠/选卡 → 列表显示实付与省下；概览"本月优惠合计/最省的卡"正确。

4. 房贷口子：录一笔提前还款 → 剩余本金与后续月供按预期重算；改商贷利率 → 后续月供据新利率重算。
5. 概览两口径数字正确：本月支出（消费+利息）与本月现金流出（含房贷全额）分别对得上；信用卡消费只算一次（不因"还卡"重复）。
6. 导出备份 → 删 app 重装 → 导入恢复，数据完整。
7. 杀进程重开数据仍在（SwiftData 持久化）。

# 【本次任务】开发规范 + 多-agent 流水线落地

## Context（为什么做）

代码 MVP 已写好并推送（分支 `claude/expense-tracker-design-h2c1wi`，目录 `ExpenseTracker/`，22 个 Swift 文件 + 单元测试 + README + XcodeGen 配置）。用户要**固化一套开发规范**：每个功能"先架构设计→再开发→必做白盒测试→功能测试→代码检视→性能测试"，每步由专门 agent 负责。

**关键现实**：本会话在云端 Linux，无 Xcode，**编译/功能/性能测试只能在 Mac 上跑**。用户已确认：
- 把 **Claude Code 装到 Mac 本地**跑流水线（本地有 Xcode，全流程含功能/性能能真正自动跑通）。
- **5 步合并为 4 个角色**。
- 用 **`.claude/agents/` 子agent 定义 + 规范文档**固化。

这些都是纯文本，云端即可编写并推送；用户在 Mac 拉下分支后，本地 Claude Code 自动发现这 4 个子agent，即可按规范开发。

## 4 个角色（由用户的 5 步 + 隐含开发步合并而来）

| 角色 | 文件 | 职责 | 在哪跑 |
|---|---|---|---|
| **架构师 architect** | `.claude/agents/architect.md` | 每个功能**开发前**：分析需求、复用现有模式、产出/更新设计文档到 `docs/design/<feature>.md` | 云端/Mac 均可 |
| **开发工程师 developer**（含白盒测试） | `.claude/agents/developer.md` | 按设计文档实现功能 + **同步编写 XCTest 单元/白盒测试**（重点 `Finance/` 算法、汇总、备份） | 云端/Mac 均可 |
| **代码检视员 reviewer** | `.claude/agents/reviewer.md` | 对 diff 做**独立静态检视**，只报告不改（核对不变量：信用卡不重复计、本金不算支出、两口径正确、Decimal、SwiftData 关系、强解包/循环引用） | 云端/Mac 均可 |
| **验证工程师 verifier**（功能+性能合并） | `.claude/agents/verifier.md` | 在 **Mac** 上：`xcodegen generate` → `xcodebuild` 编译 → 跑单测 → 模拟器功能测试（按"验证方式"清单）→ 轻量性能观察（启动、列表滚动、大数据量） | **仅 Mac** |

**合并理由**：① 开发与"写白盒测试"合并（TDD，同一上下文写代码+测试，减交接）；② 功能测试 + 性能测试合并为"Mac 端验证"（都依赖 Xcode/模拟器；极简本地 app 性能先轻量观察，不单设重型环节）；③ 代码检视保持**独立**（独立性是检视的价值所在）。

## 每个功能的流水线（写进 `DEV_PROCESS.md`）

```
① 架构设计 architect  →  产出 docs/design/<feature>.md  →【人确认】
② 开发+白盒测试 developer  →  代码 + XCTest 单测
③ 代码检视 reviewer  →  findings 清单  →  developer 修复（回到②直至无阻断项）
④ Mac 端验证 verifier  →  编译 + 单测 + 功能 + 性能  →  报告
⑤ 全绿  →  commit / 更新 PR
```
**门禁**：无设计文档不开发；检视有阻断项不进验证；验证不全绿不合并。

## 要创建的文件

- `.claude/agents/architect.md`、`developer.md`、`reviewer.md`、`verifier.md`
  —— 标准 Claude Code 子agent 格式（YAML frontmatter: `name`/`description`/`tools`/`model` + 正文系统提示）。各自工具权限按职责收敛（如 reviewer 只读 + `git diff`；verifier 给 `Bash` 跑 `xcodebuild`/`xcrun simctl`）。
