# 设计文档：<功能名>

> 由 `architect` 子agent 产出。开发前需经人确认（流程门禁）。
> 文件命名：`docs/design/<feature>.md`，`<feature>` 用简短英文短横线（如 `monthly-budget`）。

## 1. 目标与背景
- 这个功能解决什么问题、属于哪个版本（MVP / 阶段 2…）。
- 明确**范围内**与**明确不做**，防止范围蔓延。

## 2. 影响的模块 / 文件
- 列出会新增/修改的文件（`Sources/Models|Finance|Views|Seed|Backup`、`Tests/`）。
- 指出可**复用**的现有类型/方法（给出路径），避免重复造轮子。

## 3. 数据模型变更
- 新增/修改的 SwiftData `@Model`、字段、关系与删除规则。
- 是否需要数据迁移；金额字段确认用 `Decimal`。

## 4. 关键算法 / 公式
- 计算逻辑、边界条件（零值、末期、空集合等）。
- 与产品不变量的关系（信用卡不重复计 / 本金不算支出 / 两口径）。

## 5. UI 流
- 涉及的页面、交互步骤、默认值与最少点击路径（守"记一笔要快"）。

## 6. 测试点清单（供 developer 写白盒测试）
- 逐条列出需覆盖的用例，含正常、边界、异常。
- 标注哪些是纯逻辑可单测、哪些需 `verifier` 在 Mac 上人工/UI 验证。

## 7. 风险与取舍
- 已知风险、性能考量、放弃的替代方案及原因。

## 8. 开发任务拆解
- 按可独立提交的小步列出，供 `developer` 执行。
