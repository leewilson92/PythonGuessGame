# PRD：<功能名>

> 由 `product-manager` 子agent 产出。这是**产品方案**（做什么 / 为什么 / 给谁 / 做到什么算完成），**不含技术实现**——实现方案见 `docs/design/<feature>.md`。
> 开发前需经人确认（流程门禁）。文件命名：`docs/prd/<feature>.md`，`<feature>` 用简短英文短横线（如 `transaction-edit`）。
> 状态：草拟 / 待确认 / 已确认 / 已交付

## 1. 背景与问题
- 用户遇到的问题、痛点、触发场景。
- 与产品定位（极简、本地、无网络无注册无广告、记一笔要快）的关系。

## 2. 目标与用户价值
- 这个功能让用户能做什么、带来什么价值。
- 属于哪个版本（MVP / 阶段2…）。

## 3. 用户故事
- 作为<用户>，我想<做某事>，以便<达成目的>。

## 4. 功能需求
- 逐条列出该有的行为（编号 FR-1、FR-2…），各自标优先级 P0 / P1 / P2。

## 5. 验收标准（可测，供 verifier 核对）
- 逐条"什么操作 → 期望结果"，要能被功能测试或人工验证核对。

## 6. 范围边界
- **本期做**：…
- **明确不做 / 推迟**：…（防止范围蔓延）

## 7. 对现有功能与数据的影响
- 影响到的现有页面 / 功能 / 数据。
- 是否触及产品不变量（信用卡不重复计 / 本金不算支出 / 两口径 / Decimal）。

## 8. 开放问题（需向用户确认）
- 还没定的产品决策，逐条列出。**确认前不进入技术设计。**
