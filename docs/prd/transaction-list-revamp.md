| 决策点 | 结论 |

## 1. 背景与问题

当前记账列表（`Views/Transactions/TransactionListView.swift`）的现状与痛点：

- **没有"月"的概念**：列表 `@Query` 把**全部交易**按"天"分组（`Section` 头是某天 + 当日支出小计），随着记账越来越多，列表无限向下堆叠，用户想看"这个月一共花了多少 / 上个月花了多少"得自己上滚下滚、心算，看不到月度全貌。
- **看不到当月汇总**：列表里只有"当日支出"小计，没有"本月收入 / 本月支出"的汇总。概览页虽有"本月支出"，但那是**固定当月**且口径含房贷，无法回看历史月份的纯交易收支。
- **行标题不够直观**：`TransactionRow` 现在**主标题是分类名**（如"餐饮"），备注是底下的小字（如"烧烤"）。但日常记账时用户脑子里记的是"烧烤""冰粉""丝袜"这种**具体的事**，分类只是归类。主标题显示分类、把具体内容压成小字，扫一眼列表时反而要多看一行才知道这笔是干嘛的。

参考"鲨鱼记账"的排版（**仅排版**）：① 列表顶部有"月份头"，可切月、显示当月收支汇总；② 每行**备注当主标题**、分类只剩图标。这两点排版能直接缓解上面的痛点，且**不引入任何臃肿**（不引入功能宫格、发现页、运营位、网络）。

与产品定位的关系：本需求是**纯排版/信息架构优化**，让"看账"更清爽，**不改任何计费 / 汇总口径、不碰房贷算法、不加网络/注册/广告**，符合"极简、打开即用、本地优先"；也不增加"记一笔"的操作步骤（不拖慢日常记账）。

## 2. 目标与用户价值

- **按月看账**：列表能聚焦到某个月，并一眼看到该月的收入 / 支出汇总；想回看历史月份可切换。
- **一眼读懂每笔**：行标题优先显示用户自己写的备注（"烧烤""冰粉"），扫列表更快；分类用图标表达，不占标题。
- **保持极简**：只采纳排版优点，不引入鲨鱼的功能堆叠；不增加记账步骤、不引入网络。
- 版本归属：属 **MVP 体验打磨 / 列表排版优化**（在已有 CRUD、月度预算之后的体验增量），不是新阶段功能，不触及 v2 的资产/收入端/同步等范畴。

## 3. 用户故事

- 作为记账的人，我想在记账列表顶部**看到当前所选月份**，并能**切换到上 / 下个月**，以便回看某个月的账，而不是从一长串流水里翻找。
- 作为记账的人，我想在月份头**一眼看到这个月的收入和支出合计**，以便快速了解本月收支概况，不用自己心算。
- 作为记账的人，我打开记账页时希望**默认就停在当月**，以便最常见的"看本月花了啥"零操作可达。
- 作为记账的人，我扫列表时想**先看到我写的备注**（"烧烤""冰粉""丝袜"），以便一眼知道每笔是干嘛的；没写备注的，**回落显示分类名**，仍然认得出。
- 作为记账的人，我希望每行仍有**分类图标**，以便在没看文字时也能凭图标快速辨认类型。

## 4. 功能需求

> 优先级：P0 = 本期必做；P1 = 本期尽量做；P2 = 可推迟。
> 凡标 ⚠️ 的条目，其最终行为**取决于第 8 节开放问题的结论**，确认前不进入技术设计。

### A. 月份头（Month Header）

- **FR-A1（P0）顶部月份头**：记账列表（`TransactionListView`）顶部固定显示一个"月份头"，标明**当前所选月份**（如"2026 年 6 月"）。
- **FR-A2（P0）默认当月**：进入记账页默认所选月份 = **当前自然月**（今天所在月）。
- **FR-A3（P0）月份切换**：用户可把所选月份切到**上一月 / 下一月**。⚠️具体交互形式（▼ 弹月份选择器 / 上下月箭头 / 左右滑，可多选其一组合）见开放问题 Q3。
- **FR-A4（P0）列表随所选月份显示**：列表内容**只显示所选月份内的交易**（按现有"按天分组 + 当日支出小计"在月内继续分组）。切月后列表内容随之替换。
- **FR-A5（P0）月份头显示当月收支汇总**：月份头展示**所选月份的收入合计与支出合计**。
  - 口径明确：**= 该月交易（`Transaction`）按 `kind` 求和**——支出合计 = 该月所有 `kind == .expense` 的 `actualAmount` 之和；收入合计 = 该月所有 `kind == .income` 的 `actualAmount` 之和。
  - **不含房贷**：房贷还款是 `LoanPayment`，不在交易列表里，**不计入本列表的月汇总**。
  - ⚠️是否额外显示"结余 = 收入 − 支出"见开放问题 Q2。
- **FR-A6（P1）金额一律 Decimal、走统一格式化**：月汇总金额计算用 `Decimal`、展示走 `Money.string`（与全 App 一致，不引入 `Double`）。
- **FR-A7⚠️（依 Q5）空月份处理**：当所选月份没有任何交易时，列表区显示友好空态（如"本月还没有账目"），**月份头仍在、可继续切月**，收入/支出显示为 0（如 ¥0.00）。具体文案/形态见开放问题 Q5。

### B. 行标题：备注优先

- **FR-B1（P0）备注优先做主标题**：`TransactionRow` 的**主标题**改为：**备注非空时显示备注**（如"烧烤""冰粉""丝袜"）；**备注为空时回落显示分类名**（如"餐饮"）。
- **FR-B2（P0）保留分类图标**：每行左侧仍显示分类图标（`category.icon`，无分类时沿用现有 `"circle"` 占位），不因备注优先而去掉图标。
- **FR-B3（P1）⚠️分类名作为次要信息**：当主标题用的是**备注**时，分类名是否仍以**次要小字**显示（鲨鱼是"只图标 + 备注"，不再显示分类文字）见开放问题 Q4。当主标题已回落为分类名时，不重复再显示一行分类名。
- **FR-B4（P0）金额/优惠/支付方式展示不回退**：行右侧金额（带 +/− 与收入绿色）、"省 X"优惠、以及现有的支付方式小字展示**保持现状能力**（不因本次排版调整而丢失信息；支付方式小字的去留并入 Q4 一并考量）。

### 跨功能一致性

- **FR-X1（P0）不改任何计费 / 汇总口径**：本期是列表排版 + 月度筛选 + 月内收支汇总，**不改变概览的两种总口径定义**（本月支出 = 消费实付 + 房贷利息；本月现金流出 = 消费实付 + 房贷全额还款）。列表月份头的"收入/支出合计"是**该列表自己的、仅交易口径的展示**，与概览口径**并存、各管各**（见第 7 节与 Q2/Q6）。
- **FR-X2（P0）不影响"记一笔"默认值**：记一笔的默认日期仍为**今天**（不随列表所选月份变化）。⚠️"在非当月浏览时点 + 记一笔，新记的这笔默认日期仍是今天"这一行为请在 Q7 确认。
- **FR-X3（P0）现有交互不回退**：交易行点击进详情、左滑删除等现有能力保持可用；切月后这些能力对当月列表项仍生效。

## 5. 验收标准（可测，供 verifier 核对）

### 月份头与按月显示
- AC-1：打开记账页 → 顶部出现月份头，显示**当前自然月**（今天所在月，如"2026 年 6 月"），列表只显示该月交易。
- AC-2：月份头显示**该月收入合计与支出合计**，数值 = 该月交易按 `kind` 求和（支出 = 该月 `expense` 实付之和；收入 = 该月 `income` 实付之和），**不含任何房贷还款金额**。
- AC-3：把月份切到**上一月** → 列表内容替换为上月交易，月份头标题与收支汇总同步更新为上月数据；再切回**下一月**回到当月，数据一致。
- AC-4：在当月**新记一笔支出**（金额 X） → 当月支出合计立即增加 X；该笔出现在当月列表对应日期分组下；上月汇总不受影响。
- AC-5：把当月某笔**从支出改为收入**（编辑保存） → 当月支出合计减少、收入合计增加相应金额（回归交易编辑后列表/汇总同步）。
- AC-6：删除当月某笔交易 → 当月对应收/支合计随之减少，该笔从列表消失。
- AC-7（依 Q5）：切到一个**没有任何交易的月份** → 列表区显示空态文案、月份头仍在且可继续切月，收入/支出显示为 ¥0.00。
- AC-8：当月内仍**按天分组**、每天仍显示"当日支出"小计（现有行为在月内保留，不因加月份头而丢失）。

### 行标题：备注优先
- AC-9：记一笔**带备注**（如备注"烧烤"，分类"餐饮"） → 列表该行**主标题显示"烧烤"**，左侧显示"餐饮"的分类图标。
- AC-10：记一笔**不带备注**（分类"交通"） → 列表该行**主标题回落显示"交通"**（分类名），左侧显示交通图标；不出现空白主标题。
- AC-11：把一笔原本无备注的交易**补上备注**并保存 → 该行主标题从分类名变为新备注；反之**清空备注**则主标题回落为分类名。
- AC-12（依 Q4）：当主标题为备注时，分类名是否另行以小字显示，按 Q4 结论核对（结论=保留则应看到分类小字；结论=只图标则不应看到分类文字）。
- AC-13：行右侧金额仍带正确符号与颜色（支出 −、收入 +、收入绿色），有原价的仍显示"省 X"（回归，未因排版调整丢失）。

### 不变量与口径回归（必测）
- AC-14：概览页"本月支出（消费 + 利息）""本月现金流出（含房贷全额）"两个数字**保持原有口径与数值不变**（本需求未改这两个口径）。
- AC-15：列表月份头的"支出合计"与概览"本月支出"在**含房贷利息的月份**会**不相等**（列表不含房贷、概览含利息），这是**预期**且两者各自正确（口径并存，见 Q6）。
- AC-16：信用卡消费仍只算一次支出、"还信用卡"不另记（本期未引入任何重复计路径）；所有金额展示与运算无浮点误差（仍走 `Decimal`）。
- AC-17：记一笔表单的**默认日期仍是今天**，不随列表当前浏览的月份变化（依 Q7 确认）。

## 8. 开放问题 → 已全部确认（2026-06-27）

> 7 项已由用户全部拍板，**最终结论见第 0 节决策表**。下面保留各问题的原始候选作为背景；落地以第 0 节为准。

- **Q1（列表范围）记账列表改成"只显示所选月、可切月"，还是"保持显示全部交易、只在顶部加一个当月汇总头"？**
  - (a) **只显示所选月 + 可切月**（FR-A4 当前写法）：更贴近鲨鱼、更清爽，按月看账心智清晰。**产品经理倾向 (a)**。
  - (b) 仍显示全部交易（无限流水），只在顶部加"当月汇总"头，不做按月筛选：改动小，但列表越用越长、与"看某月"的诉求不完全契合。
  - > 这条决定整个 A 组功能形态，**请先定**。

- **Q2（月份头显示哪些数）月份头除"收入合计、支出合计"外，是否还要显示"结余 = 收入 − 支出"？**
  - 口径已定：**= 该月交易按 `kind` 求和，不含房贷**（房贷在 `LoanPayment`，不在交易列表）。
  - 候选：①只显示 收入 + 支出 两个数；②收入 + 支出 + 结余三个数。**产品经理倾向先只显示收入/支出两项**（当前 v1 收入端尚弱、结余意义有限），但听用户。
  - > 请确认是否要"结余"，以及三个数的主次/排版优先级（哪个最大最显眼）。

- **Q3（切月交互）用哪种切月方式？** 可单选或组合：
  - (a) 点月份标题旁的 ▼ → 弹出月份选择器（可跳到任意年月）；
  - (b) 月份标题两侧"上一月 / 下一月"箭头（`<` `>`）逐月切；
  - (c) 列表整体**左右滑**切月。
  - **产品经理倾向 (a)+(b) 组合**（箭头逐月最常用 + ▼ 跳远月份），(c) 左滑容易与行左滑删除冲突、建议慎用。请用户定。

- **Q4（行标题样式）主标题用备注时，分类名是否仍以小字显示？支付方式小字是否保留？**
  - (a) **只图标 + 备注**（最贴鲨鱼、最清爽）：主标题=备注，左侧图标即代表分类，不再显示分类文字；支付方式小字也可去掉或弱化。
  - (b) **备注为主 + 分类/支付方式仍作次要小字**（信息更全，但更密）：主标题=备注，下面仍小字显示分类名、支付方式。
  - **产品经理倾向 (a)**（贴鲨鱼、清爽；图标已表达分类），但"哪张卡更省"是本 App 卖点，支付方式信息可能仍想在行里看到——**请用户定分类小字、支付方式小字各自的去留**。

- **Q5（空月份）某月无交易时怎么显示？**
  - 候选：①整页空态卡片（如"本月还没有账目"+ 提示点 +），月份头仍在；②列表区空、月份头照常显示 ¥0.00。
  - **产品经理倾向①**（与现有"还没有账目"空态风格一致），月份头与切月始终可用，避免用户切到空月后"卡住"。请确认文案与形态。

- **Q6（与概览/预算"本月"是否联动）列表可切月，但概览页与月度预算的"本月"目前固定当月——切到上月时，概览/预算是否要跟着变？**
  - (a) **各自独立**（**产品经理倾向**）：列表所选月份只影响列表自己；概览/预算永远看"当前自然月"。心智简单、改动小、不破坏概览口径页定位。
  - (b) **联动**：列表切到某月，概览/预算也展示该月——需要把"所选月份"提升为全局状态，改动与复杂度都更大，且概览口径页本意是"看本月财务全貌"，回看历史月份是另一个诉求（更适合未来的"统计/历史"页）。
  - > 本期默认 (a) 不联动。请确认可接受"列表能切月、概览仍只看当月"这一差异。

- **Q7（记一笔默认日期）确认：在列表浏览非当月时点"+"记一笔，新记这笔的默认日期仍为今天（不随浏览月份变）。**
  - **产品经理倾向"仍为今天"**（默认日期=今天是既有约定，符合"记一笔记的是此刻发生的事"）；用户若改主意可在表单里手动改日期。
  - > 这条只需用户**确认**（不预期更改），但因涉及跨月浏览时的直觉，单列出来避免歧义。
