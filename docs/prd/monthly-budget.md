## 0. 已确认决策（2026-06-26 用户拍板）

| 决策点 | 结论 |
|---|---|
| 粒度（原 Q1）| **单一总预算**：只设一个"本月总支出上限"，**本期不做分类预算**。下文凡"按分类设预算 / 按分类已用"的表述，一律取其**"本月总预算 / 本月总已用"的等价语义**。 |
| 续期·结转（原 Q3）| **每月自动沿用上月预算、不结转剩余**；按自然月计已用、每月重新开始。模型轻：存一个"当前总预算金额"即可，**无需按月留历史**。 |
| 范围（原 Q2）| **只支出**：已用 = 本月日常消费实付合计（沿用 `dailySpending` 口径——仅支出类、自然月、信用卡不重复）。不含收入。 |
| 房贷利息（原 Q6）| **不计入**预算已用（预算只管日常消费；**绝不改动两个总口径数值**）。 |
| 呈现 + 入口（原 Q5）| 概览**新增一张「本月预算」卡**（总预算 / 已用 / 剩余 / 超支安静变红）；设预算入口放**「我的」Tab**（与分类·支付方式管理并列）。 |
| 超支提示（原 Q4）| 记账主流程**不弹窗、不拦截、不拖慢记一笔**；仅在预算卡/概览**安静呈现**：到/超 100% 变红 + 文案"超支 ¥X"/"剩 ¥X"（本期不做 80% 黄色预警，留后续）。 |
| 未设预算（原 Q7）| **N/A**：单一总预算无"分类是否设预算"之分；未设总预算时预算卡显示友好空态 + 引导去设。 |

> 因选了"单一总预算"，第 4/5 节中按分类的 FR/AC 本期**只取总预算等价语义**（例：AC-6 → 设总预算 2000、本月消费实付合计 800 → 显示"已用 800 / 剩余 1200"）。分类级预算留作后续 backlog。

## 1. 背景与问题

当前 App 只能**回看**已经花了多少（概览的"本月支出""本月现金流出""本月优惠"都是事后汇总），但没有任何**事前约束 / 进度感**：用户没法给自己定一个"这个月吃饭别超过 X 元"的目标，也就不知道月中花到一半时是不是该收着点了。

- 现状：`Finance/MonthlySummary.swift` 已能按自然月汇总日常消费实付（`dailySpending`，仅支出类交易），但**没有按分类的"已用"维度**，也没有"目标值（预算）"这个概念。
- 现状：`Models/Category.swift` 的分类带 `kind`（支出/收入）、`icon`、`sortIndex`，**没有预算字段**。
- 现状：概览（`Views/Overview/OverviewView.swift`）是四张只读 `StatCard`，记账列表（`Views/Transactions/TransactionListView.swift`）按日分组显示当日支出小计，二者都**不体现任何预算/剩余**。

痛点：想控制开销的人，缺一个"还能花多少 / 是否超了"的即时反馈。这是市面记账软件的常见能力，用户希望本 App 也有，但要**符合本 App 极简、不打扰的调性**——预算是辅助参考，绝不能因为它而让"记一笔要快（3 秒）"变慢，也不能动不动弹窗打断记账。

与产品定位的关系：预算属于**阶段2**（见 `docs/PRODUCT_PLAN.md` 第 147 行路线图，"月度预算"列在阶段 2；第 67 行 MVP "明确不做"清单也含"预算"）。本 PRD 即把该路线图项落成可执行方案。全程仍然本地、无网络、无注册、无广告。

## 2. 目标与用户价值

- **设目标**：用户能给（支出）分类设置一个月度预算金额，表达"这个月这类最多想花多少"。
- **看进度**：日常记账与概览能即时看到"已用 / 剩余 / 是否超支"，对本月开销有掌控感。
- **不打扰**：超支只做**安静的视觉提示**（颜色/文案），不打断记账流程（是否在记账时也提示见开放问题 Q4）。
- 版本归属：**阶段2** 的第一个增量。不触及资产/收入端/iCloud 同步/Face ID 等其他阶段2项；本 PRD 只做预算。

## 3. 用户故事

- 作为想控制开销的人，我想**给"餐饮"分类设一个每月预算**（如 2000 元），以便给自己立个花钱上限。
- 作为正在记账的人，当我记完一笔餐饮后，我想**顺带看到这个月餐饮还剩多少能花**，以便决定接下来是不是要省着点。
- 作为关注整体的人，我想在**概览里一眼看到本月各预算分类的使用进度**（已用/剩余、有没有超），以便快速了解全月开销节奏。
- 作为已经超支的人，我想**清楚地知道哪类超了、超了多少**，但我不希望每记一笔就被弹窗打断。
- 作为习惯每月重新规划的人，我想知道**这个月的预算是会自动沿用上月、还是要我重新设**（见开放问题 Q3）。
- 作为没给某些分类设预算的人，我希望**那些没设预算的分类不要乱入预算视图里碍事**（具体怎么显示见开放问题 Q7）。

## 4. 功能需求

> 优先级：P0 = 本期必做；P1 = 本期尽量做；P2 = 可推迟。
> 标 ⚠️ 的条目其最终行为**取决于第 8 节开放问题的结论**，确认前不进入技术设计。

### A. 设置与管理预算

- **FR-A1（P0）给分类设预算**：用户可为**支出类分类**设置一个月度预算金额（`Decimal`，> 0）。⚠️是否也支持"单一总预算"或"收入分类预算"见开放问题 Q1 / Q2。
- **FR-A2（P0）修改 / 取消预算**：已设预算的分类可改预算金额，也可**取消预算**（取消后该分类不再纳入预算统计）。
- **FR-A3（P0）预算管理入口**：提供一个集中设置预算的位置。建议放在已有的「我的」Tab（`ProfileView`，现已收纳分类管理 / 支付方式管理 / 数据备份），新增一项"预算"。⚠️最终入口与是否同时支持"在分类编辑页就地设预算"见开放问题 Q5。
- **FR-A4（P0）金额用 Decimal**：预算金额一律 `Decimal`，与全 App 一致，不引入 `Double`。

### B. 进度与超支呈现

- **FR-B1（P0）按分类算已用/剩余**：对每个设了预算的分类，按**自然月**统计本月该分类的"已用"（口径见 FR-B4 与 Q6），并派生"剩余 = 预算 − 已用"。**已用与剩余尽量计算得出、不冗余落库**（与现有"优惠/负债剩余为派生值"的不变量一致）；预算金额本身需要持久化。
- **FR-B2（P0）超支判定与提示**：当某分类"已用 > 预算"即为**超支**，需有**安静的视觉提示**（如进度条变色、剩余显示为负并标红、文案"已超 X"）。⚠️具体呈现形式见开放问题 Q4。
- **FR-B3（P0）概览体现预算**：概览页能体现本月预算使用情况（各预算分类的已用/剩余/是否超支，或一个总预算进度）。⚠️以"新增预算卡片 / 新页 / 概览下钻"中的哪种形式呈现，见开放问题 Q5。
- **FR-B4（P0）口径与不变量**：预算"已用"**只统计日常消费实付的支出类交易**（沿用 `MonthlySummary.dailySpending` 的支出口径思路），**不改变现有任何计费/汇总口径**。⚠️**房贷利息是否计入某个"居住/还贷"类预算的已用，见开放问题 Q6（默认倾向不计入，预算只管日常消费分类）。** 信用卡消费仍只在刷卡当时算一次、不因"还卡"重复计入预算已用。
- **FR-B5（P1）记账后可见进度**：记一笔（或编辑）保存后，若该笔分类设了预算，用户能**方便地感知**该分类的最新进度（在列表/概览看到更新即可，是否在记账表单内就地显示见 Q4）。
- **FR-B6（P2）没设预算的分类的展示**：⚠️预算视图里如何对待"没设预算的分类"（隐藏 / 灰显/折叠 / 显示已用但无上限），见开放问题 Q7。

### 跨对象一致性

- **FR-X1（P0）不破坏不变量**：本功能是**只读统计 + 一个新的目标值字段**，**不改变任何计费/汇总口径**。两种口径（本月支出 = 消费实付 + 房贷利息；本月现金流出 = 消费实付 + 房贷全额还款）维持不变；房贷本金不算支出；金额仍 `Decimal`；优惠/负债剩余/预算已用均派生不落库（仅预算金额落库）。
- **FR-X2（P0）空态与边界友好**：一个预算都没设时，预算视图显示友好空态、不崩溃；某分类被删除时其预算应随之失效/清理（⚠️与 crud-completion 的 `.nullify` 删除策略如何协同见开放问题，可作为 architect 关注点在设计阶段细化）；预算为 0 笔交易时"已用"显示 0、"剩余"= 预算。
- **FR-X3（P1）备份兼容**：若预算数据需要持久化（预算金额必然要存），导出/导入备份应**包含预算**，换机导入后预算不丢。具体存储与备份格式由 architect 定，PRD 在此点名要求"备份要带上预算"。

## 5. 验收标准（可测，供 verifier 核对）

> 以下"操作 → 期望结果"供功能测试或人工验证核对。凡依赖开放问题结论的条目已标注，结论确定后由本 PRD 收敛。

### 设置预算
- AC-1：进入预算设置入口 → 能看到可设预算的（支出）分类列表，并可给某分类（如"餐饮"）输入一个预算金额并保存。
- AC-2：给"餐饮"设预算 2000 后再次进入设置 → 该分类显示已设预算 2000（持久化生效，杀进程重开仍在）。
- AC-3：把"餐饮"预算从 2000 改为 1500 并保存 → 各处显示的预算上限、剩余随之按 1500 重算。
- AC-4：取消"餐饮"的预算 → 该分类不再出现在预算进度视图中（或按 Q7 结论显示为"未设预算"），且不再产生超支提示。
- AC-5：预算金额输入框只接受合法金额（> 0）；清空或非法值时无法保存（与全 App 金额校验风格一致）。

### 进度与超支
- AC-6：给"餐饮"设预算 2000，本月已有餐饮消费实付合计 800 → 预算视图显示该分类"已用 800 / 剩余 1200"（或等价进度），数字与本月该分类实付合计一致。
- AC-7：继续记一笔餐饮 300 并返回 → 该分类已用变为 1100、剩余变为 900（保存后同步更新，无需手动刷新）。
- AC-8：把某分类记到"已用 > 预算"（如餐饮预算 2000、已用 2200）→ 该分类呈现**超支视觉提示**（剩余显示为 -200 / 进度条变色 / 文案"已超 200"，以 Q4 结论为准），但记账流程**未被弹窗打断**（除非 Q4 明确要在记账时提示）。
- AC-9：把一笔已计入预算的餐饮交易**删除**或**改成别的分类** → 餐饮"已用/剩余"随之回退、超支状态相应解除（派生值跟随原始交易重算）。
- AC-10：把一笔餐饮交易的**实付金额改大/改小**并保存 → 餐饮"已用/剩余"按新金额更新。
- AC-11：当月（自然月）边界正确——上个月的餐饮消费**不计入**本月已用；跨月后本月已用从该月交易重新统计（沿用现有"按自然月过滤"的口径）。

### 概览体现
- AC-12：概览页能看到本月预算使用情况（各预算分类的已用/剩余/超支，或总预算进度，形式以 Q5 结论为准）；没设任何预算时，概览不显示空的预算区块或显示友好占位（以 Q7 结论为准）。
- AC-13：概览原有四块数字（本月支出 / 本月现金流出 / 本月优惠 + 最省的卡 / 房贷剩余）**保持原样且数值不变**——新增预算不得改动这四个既有口径的值。

### 不变量回归（必测）
- AC-14：信用卡消费仍只算一次（刷卡当时），"还信用卡"不另记，也不重复计入任何预算分类的已用。
- AC-15：房贷本金仍不算支出；"本月支出（消费+利息）"与"本月现金流出（含房贷全额）"两个数字仍各自正确、未被预算功能改动（房贷利息是否计入某预算分类已用以 Q6 结论为准，但**不得影响这两个总口径**）。
- AC-16：所有预算金额、已用、剩余的展示与运算无浮点误差（全 `Decimal`）；除"预算金额"外，已用/剩余等派生值未被落库、由计算得出。
- AC-17：导出备份 → 删 App 重装 → 导入恢复后，已设的各分类预算完整恢复（FR-X3）。

## 6. 范围边界

**本期做：**
- 给（支出）分类设置 / 修改 / 取消月度预算金额（粒度以 Q1 结论为准）。
- 按自然月统计各预算分类的已用/剩余、判定超支，做**安静**的视觉提示。
- 概览体现预算使用情况（形式以 Q5 结论为准）。
- 保证四个既有口径与所有产品不变量不被破坏；预算数据纳入备份。

**明确不做 / 推迟（防止范围蔓延）：**
- **不做预算的图表/趋势**（折线、环形占比、历史月对比等统计图）——属图表统计增强，另开 PRD（图表本身也在阶段2路线图里，但与本预算 PRD 解耦）。
- **不做预算的推送通知 / 系统通知提醒**（"本月餐饮已用 80%"之类的本地通知）——超支只在 App 内安静提示；通知涉及权限与"打扰"取舍，单列后续。
- **不做跨月结转 / 累计预算**（把本月没花完的额度滚到下月）——除非 Q3 明确要做，默认不做。
- **不做"预算 vs 实际"的导出报表 / CSV**。
- **不做收入端预算 / 储蓄目标 / 净现金流目标**——收入与资产属阶段2其他模块，本 PRD 只做支出分类预算（除非 Q2 选择纳入收入分类）。
- **不碰房贷算法与两种口径定义**，不改 `Finance/` 的现有汇总逻辑（只在其上增加按分类聚合的只读派生）。
- **不做按支付方式/按卡的预算**（如"信用卡每月限额"）——本期预算只挂在分类维度。
- **不引入新的对象类型**用于"预算周期"建模，除非 Q3 的结论（结转/历史预算）要求如此（属实现层，由 architect 据结论定）。

## 7. 对现有功能与数据的影响

**受影响的现有页面 / 功能：**
- `Views/Overview/OverviewView.swift`：需新增预算使用情况的展示（卡片 / 入口 / 下钻，形式见 Q5）；原有四张 `StatCard` 的值不变。
- `Views/Settings/ProfileView.swift`（「我的」Tab）：建议新增"预算"管理入口（见 FR-A3 / Q5）。
- `Views/Transactions/TransactionListView.swift` / `AddTransactionView.swift`：是否在记账列表或记账表单内体现某分类预算进度，取决于 Q4；默认不改记账主流程、不拖慢记一笔。
- `Finance/MonthlySummary.swift`：本身的两种口径**不改**；但本功能需要一个"按分类聚合本月已用"的只读派生维度（当前 `dailySpending` 是整月支出合计，没有按分类拆分）——这是**新增的派生统计**，由 architect 决定放在哪里（扩展现有汇总或新建一个预算汇总），PRD 只要求其口径与 `dailySpending`（仅支出类、自然月、信用卡不重复）一致。
- `Views/Settings/CategoryManageView.swift` / `CategoryEditView.swift`：若 Q5 选择"在分类编辑页就地设预算"，会受影响。

**数据 / 模型影响：**
- 需要持久化"分类的月度预算金额"。⚠️其落点（给 `Category` 加一个 `monthlyBudget` 字段 / 新建独立的预算模型以支持历史预算与周期）取决于 Q1（粒度）与 Q3（是否结转/沿用/留历史）——**这是本功能最需要先拍板的两点**，由 architect 据结论定模型，PRD 不预设实现。
- 已用/剩余/超支均为**派生计算**，不落库（与"优惠、负债剩余为派生值"的不变量一致）；唯一新增持久化的是预算目标金额。
- 备份（`BackupManager` / `Backup`）：预算金额需纳入导出/导入（FR-X3 / AC-17）；具体格式由 architect 评估兼容性。
- 与 crud-completion 的删除策略协同：删除一个设了预算的分类时，其预算应随分类一并失效/清理（现状分类删除走 `.nullify` 让交易引用置空），这点请 architect 在设计时与现有删除规则对齐。

**产品不变量核对：**
- 信用卡不重复计：预算已用只统计原始支出交易一次，不引入"还卡"路径。✅
- 房贷本金不算支出：本期不碰房贷与两种总口径；房贷利息是否进某预算分类仅为 Q6 的开放项，且**不得改动两个总口径**。✅
- 两种口径并存：定义与数值均不变。✅
- 金额 `Decimal`：预算金额与已用/剩余全程 `Decimal`。✅
- 派生值不落库：已用/剩余派生计算；仅预算目标金额落库。✅

## 8. 开放问题 → 已全部确认（2026-06-26）

> 7 项已由用户全部拍板，**最终结论见第 0 节决策表**。下面保留各问题的原始候选作为背景；落地一律以第 0 节为准。

- **Q1（最关键，决定粒度与模型）预算粒度——按分类 / 单一总预算 / 两者都支持？**
  - (a) **仅按分类**：每个支出分类各设各的预算（如餐饮 2000、交通 500）。最贴近"控制某类开销"的诉求，但用户要逐类设。
  - (b) **仅单一总预算**：只设一个"本月总开销不超过 X"，看总进度。最简单，但不知道是哪类超的。
  - (c) **两者都支持**：既有总预算、又能分到各分类。最强但最复杂（要处理"分类预算之和 vs 总预算"的关系）。
  > 这决定数据模型与所有进度/超支的展示维度，**必须最先定**。倾向极简的话，建议先做 (a) 或 (b) 其一。

- **Q2 预算只针对支出分类，还是也包含收入分类？**
  - 收入分类（工资/其他）设"预算"语义模糊（收入一般是目标/预期而非上限）。默认**只做支出分类预算**。请确认是否同意，或是否想把收入也纳入（如"本月收入目标"）。

- **Q3 预算周期与延续性——自然月固定；每月是否自动沿用上月预算？是否支持结转剩余？**
  - **周期**：默认按**自然月**（与现有汇总口径一致）。确认无误？
  - **沿用**：到了新的一月，上月设的预算是**自动延续**（餐饮一直是 2000，省心）还是**每月清零、需重设**（更灵活但麻烦）？
  - **结转剩余**：本月没花完的额度**滚到下月**吗？（如餐饮剩 200，下月预算变 2200）默认**不结转**。是否需要？
  > 若要"留每月历史预算/结转"，模型需按"周期 + 分类"建预算记录（更重）；若"一直沿用、不留历史、不结转"，给分类挂一个固定预算金额即可（轻）。这与 Q1 共同决定模型重量。

- **Q4 超支如何呈现？颜色 / 文案 / 是否在记账时也提示（守"不打扰"）？**
  - **呈现形式**：进度条变色（绿→黄→红）？剩余显示为负并标红？文案"已超 X"/"剩 X"？要哪几种、阈值如何（如用到 80% 变黄、100% 变红）？
  - **是否在记账时提示**：记完一笔导致超支时，是只在概览/预算页安静变红，还是也要在记账表单/列表给个提示（如保存后 toast"餐饮已超预算"）？
  > 产品定位是"超支提示但**不打扰记账**"。默认倾向：**记账主流程不弹窗、不拦截**，只在预算/概览视图安静呈现。请用户确认接受这个"安静"程度，或指定想要的提示强度。

- **Q5 概览里怎么放 + 设置入口在哪？**
  - **概览呈现**：(a) 概览页**新增一张预算卡片**（紧凑展示总进度或 top 几个分类）；(b) 概览里放一个**入口**，点进**独立预算页**看全部分类进度；(c) 概览**下钻**（点某项展开明细）。哪种？
  - **设置入口**：在「我的」Tab（`ProfileView`）新增"预算"项集中设置（推荐，与分类/支付方式管理并列）？还是在**分类编辑页就地**给该分类设预算？或两者都要？
  > 这关系信息架构与是否新增页面，请用户定方向。

- **Q6 房贷利息是否计入预算口径？**
  - 默认倾向：**不计入**——预算只管"日常消费分类"，房贷利息走房贷模块、不挂到某个消费分类的预算已用里（避免与"本月支出"口径纠缠）。
  - 若用户希望把房贷利息也纳入某个"居住/还贷"预算来看"全月固定开销"，需明确：① 挂到哪个分类；② **绝不能改动**"本月支出 = 消费实付 + 房贷利息"和"本月现金流出 = 消费实付 + 房贷全额还款"这两个总口径的数值。请用户定。

- **Q7 没设预算的分类在预算视图里怎么显示？**
  - (a) **完全隐藏**：只显示设了预算的分类（最干净，但看不到"其它没设预算的也花了不少"）。
  - (b) **灰显 / 折叠在底部**：显示"未设预算"的分类及其本月已用，但不参与超支判定，可点击就地补设预算。
  - (c) **显示已用、无上限条**：列出但不画进度/不判超支。
  > 影响预算视图的信息密度与"是否引导用户给更多分类设预算"。请用户选其一。
